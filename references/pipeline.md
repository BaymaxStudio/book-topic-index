# 流水线原理与排障

## 数据流

~~~
PDF ──┬─ 文字层≥200字 ──▶ pdftotext -bbox ──┐
      └─ 否则 ──────────▶ bin/ocrpdf(Vision)─┴─▶ lines.jsonl
                                                    │
                          book.json(terms/noise) ───┼─▶ scan.py ─▶ 命中明细 + annotations + 报告.md
                                                    │
                                                    └─▶ audit.py（零漏检对账）
~~~

统一中间格式 lines.jsonl，每行一页：

~~~json
{"page":1,"w":1811,"h":2629,"lines":[{"t":"文本","x":0.084,"y":0.089,"w":0.827,"h":0.021,"c":0.95}]}
~~~

x/y/w/h 归一化到 0~1，**原点左上**（与 Vision 一致）。写回 PDF 高亮时再做 y 翻转：
PDF 坐标 y = 页面高度 − 归一化 y 顶部 − 行高。

## 段落切分

中文书正文的版面特征是稳定的：左边距固定、首行缩进约 2 字符、行距均匀。
于是切段只用两个信号：

- **缩进**：某行 x 比本页最小 x（左边距）大 0.026 以上 → 新段落开始；
- **行距**：相邻行间距 > 中位行距的 1.7 倍（下限 0.0075）→ 新段落开始。

标题单独成块：匹配 第X章/第X节、一、二、三、（一）、1. 等模式，或行高显著大于
中位数（>1.18×）且长度 ≤30。

切完段落，段内各行用**空串**拼接（不加换行、不加空格），这样 "…非意识" + "形态性…"
会还原成 "…非意识形态性…"。这是整个流程里最关键的一步。

## 页码校准

每页取页眉/页脚区（y<0.085 或 y>0.955）里的纯数字行，得到 (PDF页, 印刷页) 对，
算 PDF页 − 印刷页，取**众数**。

- 为什么用众数：目录页、插图页、章节扉页的页码规律不同，平均值会被它们带偏；
  众数只认"大多数正文页"的规律。
- 为什么留证据：把投票分布写进 统计.json。若第一名和第二名很接近，说明这本书
  的页码不规整（比如罗马数字前言 + 阿拉伯正文），需要人工确认。
- 反例：一份从 302 页书里裁出来的 36 页节选，其内部物理页是 1~36，而印刷页码
  仍是 41~76，于是校准出的偏移是 **-40**。这不是 bug，是正确的。

## 目录页的特殊处理

扫描书的目录常常把"条目文字"和"页码"排成**两行**（页码单独靠右 x>0.78）。
所以行内用点线配页码会全部失败。正确做法是按 **y 坐标就近配对**：
给条目行找一个 y 最接近、且 x>0.78 的数字行，差值小于 0.012 才认。

## 排障清单

| 症状 | 先查什么 |
|---|---|
| 命中数远少于预期 | 用 audit.py 对账；若"原文出现"也少，是 OCR 质量；若只有"明细"少，是切段或正则问题 |
| 某个关键词完全搜不到 | terms 是否漏了 \s* 容错；该词是否总被拆行 |
| 页码大量错位 | 看 统计.json 的偏移投票是否分散；确认书的页码是否分段编号 |
| 章节名串页 | 换章时是否清空了节名；页眉缺失页是否兜底 |
| OCR 明显错字 | 换 Word 文本源；或提高 dpi（pdf_lines.py --dpi 400） |
| docx 打不开或掉格式 | officecli validate；查手工 XML 的插入次序 |

## 参数默认值与调整

| 参数 | 默认 | 何时改 |
|---|---|---|
| 文字层阈值 | 200 字符 | 书正文极短时下调 |
| OCR dpi | 300 | 小字号或低质扫描上调到 400 |
| 缩进阈值 | 0.026 | 版心特别窄或特别宽时 |
| 行距倍数 | 1.7 | 段落间距被误判时上调 |
| 标题行高倍数 | 1.18 | 标题与正文同高时改用模式匹配 |
